# 가계부 톡톡 · 화면 디자인

기준일: 2026-09-26. 화면 구조·상호작용의 원본이다. 정책은 [PRD.md](PRD.md)에만, 구현 순서는 [Tasks.md](Tasks.md)에만 관리한다. [목업 모음](../design-mockup/index.html)은 서버 없이 브라우저에서 열 수 있는 정적 참고 자료다.

## 1. 적용 원칙

- 함께 승인한 화면을 기준으로 만든다. 임의의 새 샘플 화면이나 더 단순한 대체 레이아웃을 만들지 않는다.
- iPhone 16Pro와 iPhone 17 화면에 최적화하여 개발. 태블릿 전용 배치는 없다. 데스크톱버전은 나중에 생각한다.
- px는 구현 후 실제 웹/모바일에서 미세 조정한다. 목업 치수를 모든 화면에 기계적으로 강제하지 않는다.
- MD를 먼저 수정한다. HTML은 사용자 별도 요청 또는 합의한 마무리 시점에만 갱신한다.
- 목업의 예시 금액·이름·날짜는 디자인용이며 초기 DB 데이터가 아니다. 과거 `yMoney`, NULL 닉네임 문구 등은 최신 PRD가 우선한다.
- 목업의 승인 버튼/검토 설명은 서비스 UI가 아니다. 보존본에서는 검토 도구 의존을 제거하거나 숨긴다. 정적 버튼이 실제 저장/인증을 실행하지 않는다.

- 입력/로그인 전용 화면을 제외한 앱 탭·설정 세부 화면에서 탭 이동을 유지한다. 탭바/저장 버튼이 키보드나 본문을 가리지 않도록 안전 영역을 둔다.
- 시트는 아래에서 열리고 내용에 따라 커지며 최대 약 화면 90%에서 본문만 스크롤한다. 제목·닫기·하단 버튼은 접근 가능하게 유지한다.

HTML이 더 오래된 표현을 포함하면 아래 변경 사항과 PRD를 적용한다. 목업은 레이아웃/밀도의 근거이지 최신 데이터 정책을 덮어쓰는 명세가 아니다.

### 인트로

- 서비스 이름 `가계부 톡톡`, 소제목 `함께 쓰기가 가능한 공유 가계부`.
- 카카오 노란색 버튼/말풍선 로고, Apple 로고를 사용한다. 네이버는 제외한다. 인트로 배경·서비스명·보조 문구·일러스트 배경에 앱의 테마 변수를 적용한다.
- 서비스명·소제목은 상단, 확대된 달력 일러스트 로고는 화면 정중앙, 로그인 수단은 하단에 배치한다. 로고 뒤 강조 배경은 없으며 화면 테마는 유지한다. 짧은 화면에서는 최소 높이와 스크롤을 허용한다.
- Apple 버튼 아래 `아이디 로그인  |  둘러보기` 보조 링크. 이용약관/개인정보처리방침 링크는 더 낮은 위계.
- 둘러보기는 기존 달력 UI와 하단 탭 모양만 표시하고 `둘러보기 · 예시 데이터`와 로그인 복귀 링크를 둔다. 모든 기능 동작은 `로그인 후 이용 가능합니다.`를 안내하며 날짜/월/범위/필터/목록/탭 화면을 바꾸지 않는다. 필터 시트·설정·통계 화면은 열지 않는다. 실제 계정이나 기본 가계부는 생성하지 않는다.

### 아이디 회원가입

- 아이디·비밀번호·선택 닉네임을 입력하고 `가입하기`를 누른다. 이메일 확인 단계는 없다.
- 프로필 저장까지 성공하면 `가입이 완료되었습니다` 팝업 후 로그인 폼으로 전환한다. 비밀번호 찾기를 제공하지 않는다는 안내를 표시한다.
- 로그인 화면의 전환 링크 텍스트는 `회원가입`으로 표시한다. 비밀번호 안내는 화면 가운데 정렬한다.
- 닉네임 미입력 시 `tb_user.nickname`에는 `톡톡`을 저장한다.
- 확인 대기 중 비밀번호는 브라우저 저장소에 기록하지 않는다. 앱 딥링크 연결은 앱 배포 단계에서 진행한다.

### 달력·지출

- 상단 오른쪽은 테두리 없는 슬라이더 필터 아이콘. DY 프로필/선택 개수 배지는 없다.
- 달력 상단 왼쪽 콤보박스를 제거한다. 가운데 서비스명/우측 상세 필터 아이콘은 유지한다. 범위는 상세 필터에서 선택하며 금액과 목록에 함께 적용한다.
- React 화면을 상단·월 달력·일별 지출 목록으로 분리한다. 달력은 왼쪽으로 밀면 다음 달, 오른쪽으로 밀면 이전 달이다. 가로 드래그에 달력만 따라 움직이고 놓을 때 퇴장 160ms/진입 200ms로 전환한다. 짧은 드래그는 200ms 원위치 복귀, 작은 탭과 세로 스크롤은 월 이동으로 처리하지 않는다. 화살표도 같은 전환을 사용한다.
- 지출 추가·수정은 달력을 배경으로 같은 80dvh 높이의 바텀시트를 사용한다. 열기/닫기는 동일한 320ms ease-in-out 슬라이드업/다운, 내부 본문 스크롤과 하단 저장 버튼을 유지한다. 취소·바깥 영역·ESC로 닫고 저장·삭제 중 닫기는 막는다. 수정 데이터 조회 중에는 로딩/오류 화면을 시트 안에 표시하고, 수정 URL 직접 접근은 기존 페이지를 유지한다.
- 일별 합계를 날짜 숫자 아래에 원 단위 없이 표시하고 0원은 숨긴다. 배경 농도로 보조하며 선택 날짜는 별도 강조한다.
- 지출 수정 폼에는 저장 버튼과 별개의 `지출 삭제`를 둔다. 삭제 확인창에서 취소하거나 확인할 수 있으며 완료 후 원래 날짜의 달력으로 돌아간다.
- 지출 행은 `대분류(아래 작은 중분류) + 오른쪽 메모 + 금액(아래 결제수단)`이다. 아이콘 자리와 빈 아이콘 대체 기호는 없다. 분류는 고정 폭 대신 실제 글자 폭(최대 행의 35%)을 사용한다. 중분류가 없으면 빈 보조 문구를 넣지 않는다. 긴 분류·메모는 말줄임하고 금액은 우측을 유지한다. 메모 간격과 결제수단 표시의 세부 규칙은 아래 최신 지출 행 규칙을 따른다.
- 지출 폼의 가계부 선택은 개인/기존 그룹 칩. +는 없다.
- 지출 폼의 상위·하위 카테고리는 이름만 표시하며 icon_key 출력 영역은 없다. 하위가 없어도 폼 진행 가능. 이름 자체에 사용자가 입력한 이모지는 데이터로 보존한다.
- 날짜·시간 한 영역, 결제수단은 카테고리와 같은 칩. 별도 지출성격 입력란/앱 내부 숫자 키패드는 없다.
- 신규 지출 시트가 열리면 기본 다이얼로그 포커스가 취소 버튼에 남지 않도록 다음 프레임에 `#expense-amount`로 포커스한다. 상위/하위 카테고리 선택 후 결제수단 선택으로 포커스를 이동하고, 결제수단 선택 직후에는 `메모(선택)` 입력으로 이동한다.
- 모바일 전체 폼과 데스크톱의 좁은 중앙 폼은 같은 구성이다. 하단 저장 버튼 유지.

### 필터

- 상단 전체/그룹/개인 탭 → 가계부 영역 → 카테고리 → 결제수단.
- `생활비 ☑` 아래 식비·카페·장보기, `고정비 ☑` 아래 주거·통신·보험처럼 **그룹별 하나의 영역**으로 구분한다.
- 취미·반려동물처럼 그룹이 없는 항목 위에는 빈 공간만 두고 `그룹 없음`, `그룹 없음 전체` 제목은 넣지 않는다.
- 결제수단은 `카드 ☑` 아래 카드 항목, `현금 ☑` 아래 현금/추가한 항목.
- 제목 체크=소속 전체 선택. 전체 선택/부분 선택/해제를 구분하되 `세부조건 N개` 문구는 없다.
- 접힌 가계부 제목에서도 전체 선택 가능. 긴 내용만 내부 스크롤하고 달력 배경은 고정한다.
- 상세 필터의 체크박스는 전체/부분/미선택을 표시한다. 상위 칩은 본인과 하위를 함께 선택하며 하위는 아이콘 없는 개별 칩이다. 비활성 항목은 과거 내역 검색을 위해 비활성 표시와 함께 노출한다. 초기화/닫기/적용은 분리하고 적용 전에 배경 조회를 바꾸지 않는다.
- 필터 항목은 아이콘 없이 균등 3열로 배치하고 버튼 높이를 통일한다. 하위 항목은 같은 폭의 상위 항목 아래에 표시한다. 이름 길이에 따라 버튼 폭이 달라지지 않는다.

### 관리 화면

- 그룹 관리는 승인 B안 목록→상세를 기준으로 실제 정보를 표시한다. 만들기(그룹명 1~30자)/코드 참여(8자리)는 각각 하단 시트이며 성공 즉시 상세로 이동한다. 참여 오류 예시를 입력 전에 나열하지 않고 제출 후 팝업으로 안내한다. 멤버는 저장 닉네임·마스킹 계정·본인 표시, 초대 코드는 복사를 제공한다. 그룹 나가기는 영구 삭제 가능성을 항상 확인한다. 초대 코드 재발급은 후속 개발이며 MVP 화면에서 버튼을 노출하지 않는다.
- 카테고리 이름을 누르면 추가 시트와 같은 구성의 수정 시트를 열어 기존 값을 채운다. 상위는 이름·그룹을 수정하며 선택 그룹을 다시 누르면 해제한다. 하위는 이름만 수정한다. `+ 하위`는 수정과 별개의 추가 버튼이다.
- 설정의 서비스에는 내 정보 관리·테마 변경만 노출한다. 미구현 공지/건의/알림 메뉴를 넣지 않는다.
- 카테고리 추가는 우측 하단 +. 추가·수정 시트의 아이콘 영역은 제거하고 이름과 선택 그룹만 표시한다. 시트의 그룹 칩은 다시 누르면 해제. 그룹 없는 카테고리 앞에는 별도 제목을 표시하지 않는다. 그룹별 `+ 카테고리`, 그룹에서 열었다는 설명, `하위 N개 펼침/하위없음` 문구는 없다. 버튼은 `저장`.
- `카테고리 그룹` 제목 오른쪽의 `+ 그룹 추가`로 이름 입력 시트를 열고 그룹을 추가한다.
- 관리 목록에서도 아이콘과 빈 아이콘 자리 없이 이름을 표시한다. 하위 들여쓰기는 유지한다. 기존 DB 아이콘 데이터는 삭제하지 않는다.
- 그룹 제목을 누르면 기존 이름이 채워진 `그룹 수정` 시트를 연다. 그룹 ID와 소속 카테고리를 유지하고 이름만 변경한다.
- 그룹 수정 시트의 저장 아래 `비활성화`/`활성화`를 제공한다. 비활성화 확인 후 소속 카테고리를 그룹 없이 옮기고 그룹만 비활성화한다. 비활성 그룹도 표시하고 제목으로 수정/활성화할 수 있다. 이름 저장만으로 활성화하지 않으며, 활성화 후 이전 카테고리 배정은 자동 복원하지 않는다.
- 결제수단 관리는 카드/현금 고정 영역, 가계부 선택 상자, 우측 하단 SVG +를 사용한다. +에서 이름/필수 유형을 입력하고 항목 행이나 ⋮를 누르면 기존 값의 수정 시트를 연다. 유형 이동과 비활성화는 확인창으로 영향을 안내한다. 비활성 표시와 ⋮는 함께 유지한다. 미구현 순서 변경 버튼은 노출하지 않는다.
- 카테고리와 결제수단 수정 시트의 저장 아래 활성 상태에 따라 `비활성화` 또는 `활성화`를 둔다. 비활성 행도 이름/⋮로 수정 시트를 열 수 있다. 활성화는 현재 입력값 저장과 함께 수행하며 중복 이름을 확인한다. 상위 비활성화는 하위도 함께 처리하고, 상위 활성화는 상위만 복구한다. 하위 복구는 상위 활성화 후 개별 수행한다. 새 지출 선택에서는 비활성 항목을 제외한다.
- 결제수단 추가·수정 시트는 시트 바깥 배경/× 클릭으로 닫힌다. 지출 시트와 같은 320ms ease-in-out 슬라이드다운과 배경 페이드 후 제거한다. 저장·활성화·비활성화 성공 후에도 같은 닫기를 사용한다. 시트 내부 클릭은 닫지 않으며 저장 중에는 배경/× 모두 닫기를 막는다.
- 결제수단 추가/수정 시트에는 로고 선택 영역을 표시하지 않는다. 관리 목록에서 카드는 인라인 카드 선 SVG, 현금은 `₩` 문자를 유형 아이콘으로 표시한다. 외부 카드·현금 이미지 파일은 사용하지 않는다.
- 카테고리·결제수단 관리의 가계부 콤보박스는 현재 이름/화살표 영역 전체에서 열리고, 키보드 포커스 표시를 제공한다.
- 활성 상위 카테고리 오른쪽의 `+ 하위`는 부모 이름과 하위 이름 입력칸만 있는 시트를 연다. 하위 아이콘/그룹 선택은 없다. 우측 하단 추가 버튼의 `+`는 원의 정중앙에 위치한다.
- 카테고리 관리의 가계부 행 오른쪽에는 목록이 하나여도 열리는 선택 상자를 둔다. 개인 가계부 표시 이름은 저장 닉네임, 닉네임이 비었으면 `개인 가계부`다.
- 내 정보 상단 아바타+닉네임 요약 제거. 닉네임 placeholder `(선택)`, 로그아웃 우측 `실행` 제거.
- 계정 삭제 팝업 경고 아이콘은 가운데. `로그인 재인증이 완료되었습니다` 문구 없이 삭제 범위·복구 불가·확인 입력을 보여준다.
- 카카오 본인 확인 팝업은 노란색 `가계부 탈퇴하기` 버튼과 우측 상단 ×를 사용한다. 버튼은 재인증을 시작하며 최종 확인 전에는 삭제하지 않는다.
- 아이디 계정 삭제는 비밀번호 본인 확인 폼→삭제 확인 폼을 통째로 전환한다. 삭제 입력이 정확히 일치해야 제출할 수 있고 요청 중 취소/중복 제출은 막는다. 소셜 연결 계정은 해당 재인증·연결 해제가 준비되기 전 안내만 제공한다.
- 카카오 계정은 비밀번호 입력 대신 `카카오로 본인 확인` 폼을 제공한다. 재로그인 콜백에서 같은 계정을 확인한 뒤 내 정보의 삭제 확인창을 다시 연다. 확인창에는 카카오 연결 해제와 서비스 삭제의 부분 실패 가능성을 안내하며, 재로그인만으로 삭제하지 않는다. Apple 등 미지원 소셜은 계속 차단한다.
- 테마는 B안 한 줄 목록. 이름+3색 미리보기+선택 체크. 누르면 즉시 적용, 저장 버튼 없음.

## 4. 검토 방법

- 달력 지출 행은 카테고리와 메모 사이 기존 간격에 3px을 더하고, 최우측 금액 아래 작은 결제수단 상세 이름을 오른쪽 정렬한다. 상세 이름이 비었으면 카드/현금 유형을 표시한다.

- 요청이 있을 때 기존 목업을 바탕으로 후보를 비교하고 **추천안과 이유**를 함께 제시한다. 재승인된 화면을 불필요하게 다시 검토하지 않는다.
- 실제 구현 중에는 해당 화면의 정상 동작을 짧게 확인한다. 종합 접근성·반응형·오류/권한 상태 검토는 Tasks의 두 출시 게이트에서 한다.
- 이 목업 모음은 localhost·세션 키·외부 서버를 요구하지 않는다. 서비스 기능은 별도의 React 구현에서 연결한다.
