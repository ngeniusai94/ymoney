# 가계부 톡톡 · 제품 요구사항

기준일: 2026-09-26. 이 문서가 **제품 정책의 단일 원본**이다. 기존 구현은 초기화하고 확정한 기획과 UI를 재사용한다. 구현 상태는 [Tasks.md](Tasks.md), 기술 구조는 [Architecture.md](Architecture.md), 화면은 [Design.md](Design.md)를 따른다.

## 1. 제품 방향

**함께 쓰기가 가능한 공유 가계부**

개인 가계부 하나와 여러 공유 가계부를 한곳에서 관리한다. 빠른 지출 입력, 월간 달력 조회, 2인 공유가 핵심이다. React Web으로 먼저 만들고, 최종적으로 앱으로 감싸 배포한다. 모바일 기준으로 만들며 데스크톱에서도 동일한 한 열 화면을 사용한다.

- 참고 서비스: 위플 가계부, 편한가계부. 확정된 자체 목업을 우선한다.
- MVP: 인증, 둘러보기, 개인·그룹 가계부, 분류 관리, 지출 CRUD, 달력·필터, 내 정보·테마, 계정 삭제.
- 통계 탭은 MVP에서 `준비 중`으로 표시한다. 월·일 합계는 달력에서 제공한다.
- 후속: 수입, 상세 통계, 실시간 동기화, 오프라인 입력, 다크 모드, 관리자·멤버 내보내기, 공지·건의·알림, 수동 계정 병합.
- 앱 포장·스토어 배포는 프로젝트 최종 단계이며, 영구 제외 기능이 아니다.

## 2. 인증·사용자

1. 인트로의 주요 로그인 수단은 카카오와 Apple이다. 네이버는 사용자 요청(2026-10-05)으로 제외한다. 그 아래 보조 링크로 `아이디 로그인`, `둘러보기`를 둔다.
2. 보조 로그인은 아이디·비밀번호 가입/로그인이다. 아이디는 영문 소문자·숫자·밑줄 4~20자이며 대문자 입력은 소문자로 정규화한다. Supabase Auth에는 `아이디@ymoney.com`으로 저장한다. 이 주소는 개발용 임시 선택이며 도메인 소유권 확인 전 실사용 가입에 쓰지 않는다. 소셜 계정의 실제 이메일은 변환하지 않는다.
3. 공유 Auth의 Confirm Email 비활성화 전제에서 가입 직후 회원정보를 생성하고 로그인 폼으로 돌아간다. 아이디 계정의 이메일 확인·비밀번호 찾기/재설정은 제공하지 않는다. 사용자가 비밀번호를 잃으면 현재 MVP에서 복구할 수 없음을 가입 화면에 알린다.
4. 닉네임은 선택 입력이며 placeholder는 `(선택)`이다. 새 계정에서 비어 있거나 공백뿐이면 **톡톡**으로 저장한다. 과거 NULL 닉네임도 표시 시 톡톡으로 대체하되 공유 테이블의 기존 값을 일괄 수정하지 않는다.
5. 최초 소셜 가입에서도 닉네임을 건너뛸 수 있다. 로그인 후 프로필과 개인 가계부는 중복 생성되지 않아야 한다.
   - 카카오 로그인은 account_email만 요청한다. profile_image/profile_nickname을 요청하지 않으며 신규 서비스 닉네임은 톡톡으로 저장하고 내 정보에서 변경한다.
6. 신규 ymoney 프로필 번호는 `M0001`, `M0002`…로 증가한다. 기존 yWeather `W0001`… 번호와 공용 채번을 바꾸지 않는다. 동일 인증 UUID의 기존 프로필이 있으면 재사용한다.
7. 같은 이메일의 소셜·아이디 계정 연결은 실제 Supabase/공급자 설정을 확인한다. `@ymoney.com`의 소유권 확인 전 동일 이메일 자동 연결 가능성을 특히 점검한다. 확인되지 않은 이메일로 임의 병합하지 않는다. Apple 비공개 릴레이 주소는 별도 계정이 될 수 있다. 수동 연결·해제는 MVP 범위가 아니다.
8. 둘러보기는 고정 예시의 달력 화면만 표시한다. 날짜·월 이동·범위 선택·필터·지출 추가/수정·하단 탭 등 모든 기능 동작은 `로그인 후 이용 가능합니다.`를 안내하며 화면/데이터를 변경하지 않는다. 로그인 복귀 링크만 실제로 이동한다. 실제 계정/가계부를 생성하거나 조회하지 않는다.
9. 이용약관·개인정보처리방침 링크를 제공한다. 동의 이력 테이블·동의 시각·버전 저장은 만들지 않는다. 공개 배포 전 필요한 고지와 공급자 요구사항을 확인한다.

서비스 로그인 성공 기준은 유효한 Supabase Auth 세션과 **같은 UUID의 활성 `tb_user` 행(`use_yn = 'Y'`)이 모두 존재하는 것**이다. Auth 세션만 있거나 `tb_user` 행이 없으면 서비스 로그인 완료로 표시하지 않는다. 신규 계정의 `tb_user` 행은 최초 서비스 로그인 전에 생성하고, 기존 UUID의 행은 재사용한다.

아이디 회원가입에는 기존 이메일 중복 확인 RPC를 사용하지 않는다. Auth 중복 오류를 “이미 사용 중인 아이디”로 표시한다. Auth에는 있지만 `tb_user`가 없는 아이디 계정은 비밀번호 로그인 성공 후 본인 프로필을 복구한다. `M` 번호 채번은 기존 W 함수와 분리한다.

## 3. 가계부·공유 그룹

- 개인 가계부는 사용자당 하나. 공유 그룹은 여러 개를 허용하며 **그룹별 1~2명**이다. 혼자서도 그룹을 사용할 수 있다.
- 개인 가계부의 화면 표시 이름은 `tb_user.nickname`이 있으면 그 값, 없거나 공백이면 `개인 가계부`다. 공유 가계부는 저장된 그룹 이름을 표시한다. 이 규칙은 저장된 가계부 이름을 변경하지 않는다.
- 관리자 없이 모든 멤버가 지출, 분류, 결제수단, 그룹 이름, 초대 코드를 동등하게 관리한다.
- 그룹 생성은 설정의 그룹 관리에서만 한다. 달력과 지출 입력의 가계부 선택 영역에 그룹 추가 버튼을 넣지 않는다.
- 초대는 영문·숫자 **8자리 코드**만 사용한다. 링크/이메일 초대는 없다. 입력은 대소문자를 구분하지 않는다.
- MVP에서는 코드 복사만 제공한다. 초대 코드 재발급은 사용자 요청(2026-10-05)으로 후속 개발로 연기한다. 후속 재발급 시 이전 코드는 즉시 무효화한다.
- 잘못된 코드, 무효 코드, 이미 참여, 정원 초과는 참여 요청 실패 팝업으로 이유를 표시한다. 입력 전에 오류 예시를 나열하지 않는다.
- 그룹 만들기/코드 참여 성공 시 해당 그룹 상세로 이동한다.
- 본인 `그룹 나가기`만 제공한다. 한 명이 남으면 내역을 유지하고, 나간 사용자는 접근할 수 없다. 마지막 멤버가 나가면 확인 후 그룹과 하위 데이터를 영구 삭제한다.
- `그룹 삭제`, 관리자/상대방 내보내기, `1자리 남음` 배지는 MVP에 없다.
- 멤버는 저장 닉네임과 마스킹 계정을 표시한다. 이메일 아이디 앞 최대 네 글자만 노출하고 나머지는 `****`로 표시하며 도메인은 노출하지 않는다. 짧은 아이디는 전체가 드러나지 않도록 최소 한 글자를 숨긴다. 이메일 없는 경우 `계정 정보 없음`으로 표시한다. 다른 멤버의 원문 이메일을 내려받지 않는다.

## 4. 카테고리와 결제수단

### 카테고리

`생활비`는 카테고리를 선택적으로 묶는 부가 그룹이다. 필수 대분류가 아니다. 실제 분류는 **식비 → 외식**의 최대 2단계이고 메모는 별도 필드다.

- 상위 카테고리는 그룹이 없어도 되고 하위 카테고리도 없어도 된다.
- 하위 카테고리가 있더라도 상위만 선택해 지출을 저장할 수 있다. 저장 시 선택한 상위 또는 하위 ID 하나만 참조한다.
- 상위는 선택 아이콘+이름, 하위는 이름만 표시한다. 아이콘은 선택 항목이며 목록에서 선택한다. 아이콘 없음 버튼을 선택해 빈 값으로 저장할 수 있다. 하위의 그룹과 아이콘은 상위에서 따라온다.
- 카테고리는 같은 가계부 안에서 그룹을 이동하거나 그룹 소속을 해제할 수 있다.
- 관리 화면 우측 하단 `+`에서 카테고리 추가 시트를 연다. 그룹 내부의 `+ 카테고리`는 없다. 시트에서 그룹은 선택 사항이며 선택된 칩을 다시 누르면 해제된다.
- 관리 화면은 가계부가 하나여도 우측 선택 상자로 목록을 열어 선택할 수 있다.
- 하위 추가는 해당 상위 카테고리의 `+ 하위`에서 한다. 그룹 추가는 별도 동작이다.
- 이름·아이콘·정렬·활성 상태를 관리한다. 같은 가계부/유형의 상위 이름과 같은 부모의 하위 이름 중복을 방지한다.
- 사용한 분류는 기록을 잃지 않도록 비활성화한다. 신규 선택에서는 제외하고 기존 거래에는 유지한다. 그룹 정리 시 소속 카테고리는 모두 그룹 없음(category_group_id=NULL)으로 옮긴 뒤 그룹을 비활성화한다. 카테고리의 활성 상태와 지출 기록은 유지하며 하위는 상위를 따라간다.
- 상위 비활성화는 하위도 함께 비활성화한다. 하위 단독 비활성화는 상위와 다른 하위에 영향을 주지 않는다. 확인 후 실행하며 행을 삭제하지 않는다.
- 비활성 항목도 관리에서 수정/활성화할 수 있다. 활성화 시 중복 이름을 검사하고, 하위는 활성 상위 아래에서만 복구한다. 상위 활성화는 하위를 자동 복구하지 않는다.
- 분류 이름·그룹 변경은 과거 거래의 표시/필터에도 반영된다. 과거 분류의 스냅샷 테이블은 만들지 않는다.

### 결제수단

- `카드(CARD)`, `현금(CASH)`은 변경 불가능한 두 유형이다. 유형 아래의 현대카드·롯데카드·현금·지역화폐·카카오페이 등은 사용자가 관리하는 예시 항목이다.
- 항목 추가·이름 변경·유형 이동·정렬·비활성화를 지원한다. 유형 이동 시 기존 거래의 분류/필터도 달라짐을 안내한다.
- 같은 가계부/유형에서 활성 결제수단 이름은 중복되지 않는다. 사용한 항목은 비활성화하여 기존 거래 참조를 유지한다.

### 초기값과 개인화

- 새 개인/그룹 가계부의 초기 그룹은 생활비·고정비·특별비다.
- 기본 상위 카테고리 4개: 생활비의 식비·카페, 고정비의 주거, 특별비의 취미. 기본 결제수단은 CASH의 현금. 기본 하위 분류는 강제로 생성하지 않는다.
- 분류 데이터는 가계부 멤버가 공유한다. 빠른 입력의 선택 순서는 **현재 사용자·현재 가계부의 삭제되지 않은 지출 작성 이력**으로 개인화한다.
- 누적 사용 횟수 내림차순 → 최근 사용 → 관리 정렬 순서로 표시한다. 사용 이력이 없으면 관리 순서를 사용한다. 빈 폼에서 항목을 자동 선택하지 않는다.

## 5. 지출·달력·필터

### 지출

- 금액, 카테고리, 결제수단, 날짜·시간, 선택 메모를 한 화면에서 입력한다. 금액은 기기 숫자 키보드를 사용한다.
- 금액은 양수 원화 정수, 메모는 최대 200자다. 카테고리와 결제수단은 필수이며 같은 가계부의 유효 항목만 사용한다.
- 가계부 선택을 바꾸면 이전 가계부의 카테고리/결제수단 선택을 해제한다.
- 달력의 날짜 클릭은 조회만 한다. 우측 하단 `+`로 입력을 연다. 선택일이 있으면 해당 날짜, 그 외에는 현재 날짜·시각을 기본값으로 한다.
- 목록 항목을 눌러 수정한다. 삭제는 확인 후 소프트 삭제하며 합계/조회에서 제외한다.
- 공유 가계부의 두 멤버 모두 지출을 수정·삭제할 수 있다. 소프트 삭제는 거래 행을 남기고 `deleted_at`을 기록한다.
- 저장 중 중복 제출을 막는다. 실패 시 입력값을 보존하고 성공 후 달력 합계/목록을 다시 조회한다.
- 공유 지출 충돌은 MVP에서 마지막 저장 우선이다. 실시간 구독 대신 화면 복귀·월 변경 등에서 재조회한다.

### 달력

- 첫 진입은 현재 월 전체 달력이다. 지출이 0건이어도 달력을 유지한다.
- 작은 한 줄 월 총지출, 큰 달력, 선택일 합계와 한 줄 지출 목록으로 구성한다. 지난달 비교는 없다.
- 달력의 날짜 숫자 아래에는 해당 날짜 총지출을 표시하되 0원인 날에는 금액을 표시하지 않는다.
- 오늘 제목은 `오늘 지출`, 다른 날짜는 `9월 20일 지출`처럼 표시한다.
- 실제 지출이 없는 날은 `무지출에 성공하셨어요!`. 필터 결과만 없을 때는 `조건에 맞는 지출이 없어요`. 조회 실패는 별도 오류이며 0원으로 위장하지 않는다.

### 필터

- 메인 화면 상단 왼쪽에 `모두 / 개인 가계부 / 그룹 가계부` 콤보박스 퀵필터를 둔다(2026-10-05 사용자 요청). 기본값은 모두이며 같은 종류의 가계부를 합산한다. 월/일 합계·날짜별 금액·선택일 목록에 동일하게 적용한다. 별도 범위 칩은 없고 오른쪽 필터 아이콘은 상세 조건 시트를 담당한다. 상세 시트 구현 시 범위 선택과 URL scope를 함께 사용하여 상충하지 않도록 한다.
- 시트 상단 `전체 · 그룹 · 개인`이 조회 영역을 결정한다. 전체에서는 그룹과 개인을 모두, 나머지는 해당 영역만 보여준다.
- 가계부별 접기·펼치기/전체 선택 → 카테고리 → 결제수단 순서다. 각 가계부의 선택은 독립적이다.
- 카테고리 그룹 제목의 체크는 소속 항목 전체 선택이다. 그룹 없는 카테고리는 제목 없이 항목만 표시한다.
- 상위 카테고리 전체 선택에는 상위에 직접 저장한 거래와 모든 하위 거래가 포함된다. 하위도 다중 선택 가능하다.
- 카드/현금 제목 체크는 소속 결제수단 전체 선택이다.
- 같은 필터 항목끼리는 OR, 카테고리와 결제수단 간에는 AND로 결합한다. 가계부별 조건을 계산한 결과를 합친다. 전체 해제는 0건이지 전체 조회가 아니다.
- 적용 전 임시 선택과 적용된 조건을 구분한다. 초기화는 접근 가능한 전체 범위/항목으로 되돌리고 적용 시 반영한다. 필터는 URL search params로 복원한다.
- 이름이 같아도 가계부가 다른 항목은 서로 다른 ID로 관리한다.

## 6. 설정·계정 수명주기

- 서비스: **내 정보 관리 / 테마 변경**. 가계부: **카테고리 관리 / 결제수단 관리**. 별도 **그룹 관리**.
- 내 정보: 선택 닉네임 저장, 로그인 정보 확인, 로그아웃, 계정 삭제. 중복 프로필 요약 카드는 없다.
- 계정 삭제는 재인증 후 최종 확인에서 `삭제`를 입력한다. 개인 가계부와 하위 데이터 삭제, 모든 그룹 탈퇴, 마지막 멤버 그룹 삭제가 필요하다. 남은 그룹 거래의 작성자 참조는 익명화하고 `탈퇴한 사용자`로 표시한다.
- 공용 계정 삭제 함수와 다른 프로젝트 계정에 미치는 영향은 실제 연결 전에 확인한다. Apple 토큰 해제까지 포함한 탈퇴 경로가 확보되지 않으면 출시 완료로 표시하지 않는다.
- 가계부 삭제는 별도 `ymoney.fn_mon_withdraw_account`로 본인의 활성 M 계정만 처리한다. 기존 yWeather 함수는 변경하지 않는다. 공용 기기/푸시 정보가 연결된 계정이나 Apple 연결 해제가 준비되지 않은 계정은 삭제하지 않는다. 최근 5분 이내 생성된 본인 인증 세션과 `삭제` 확인값을 요구한다. 개인·마지막 멤버 그룹 데이터 및 본인 회원/Auth 계정은 영구 삭제되며, 다른 멤버가 남은 그룹의 거래는 유지한다.
- 네 가지 파스텔 테마는 선택 즉시 적용하고 브라우저에 저장한다. 인트로는 테마와 무관한 흰색·모노톤이며 다크 모드는 후속이다.

## 7. 완료 기준과 검토 시점

- 화면 하나와 그 화면의 실제 기능·이동을 연결한 뒤 다음 단계로 진행한다. 전체 화면만 먼저 만들거나 DB 기능을 일괄 선행 개발하지 않는다.
- 개발 중에는 해당 동작의 작은 수동 확인과 필요한 빌드만 한다. 자동 테스트·보안/RLS 종합 작업은 **MVP 기능 완성 시점**, **앱 출시 직전** 두 번에 모아 수행한다.
- 종합 검토 전에는 테스트 데이터로만 개발한다. 비밀키 노출 방지와 기존 권한 유지까지 미루는 뜻은 아니다. 검토 전 외부 실사용 서비스로 공개하지 않는다.
- 주요 UI는 승인되었지만 **인트로 일러스트 품질 개선은 출시 전 필수 후속 작업**이다. 공급자 설정, M 채번, 그룹 원자성, 공용 탈퇴 영향은 해당 기능 단계에서 확인할 기술 항목이다.
